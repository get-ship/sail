# Authoring SUI here

This file is GENERATED from the compiler's own vocabulary tables and the
resolved styling policy for this directory. Everything below is enforced —
an off-list value is a compile error, and the error message carries the
allowed list. Trust errors over memory.

## The hard rules (every policy)

- NO `<style>` blocks, NO `style=` attributes — ever. Visuals flow through
  tokens, props, and the surfaces listed below.
- NO raw values anywhere (no px, no hex): spend a token.
- Layout is elements, not CSS: `<row>`, `<column>`, `<grid>`, `<center>`,
  `<stack>` with `gap`/`align`/`justify`/`cols` attributes. `cols` is a fixed
  column count (1..=12) on `<grid>` and takes precedence over `min` when both
  are present. Unrecognized attributes on a layout keyword are a compile error —
  the language won't silently drop them.
- Behavior is unrestricted TypeScript in `<controller>` — the restraint is
  visual, never logical.
- Components declare their static surface in `<scope>` — TypeScript field
  syntax, types and literal values only: `props: { label = 'Default';
  tone = 'default'; kind: 'a' | 'b' = 'a' }`. `tone`/`size` are the framework
  channels. Styling tables live in `variants:`. If it computes, it goes in
  `<controller>`.

## variants — a prop whose values are sx tables

A variant IS A PROP. Declare it inside `props`, with the value being the
variant->sx table; the prop's type is the union of the keys (first = default),
and it reflects to an attribute so CSS can key on it:

```
<component>{
  props: {
    variant: { solid: 'bg-tone text-tone-fg', soft: 'bg-tone-bg', outline: 'border-tone' },
    tone: 'default' | 'primary' | 'destructive',
  },
}</component>
```

Values are sx lists and take the same state prefixes
(`solid: 'bg-tone hover:bg-tone-bg-hover'`). `compound` (a sibling field of `props`)
keys rules on COMBINATIONS of variant values.

There is no separate `variants:` block. One declaration surface: `props`.

## Motion — one system

`motion:<trigger>={{ <property>: '<preset>' }}`. There is exactly one animation
directive; `transition:` / `in:` / `out:` are retired.

TRIGGERS (hover, press, focus, focus-visible, enter, exit, view, scroll, loop) come in three kinds:

- INTERACTION — `hover` `press` `focus` `focus-visible`: rest <-> active, driven by events.
- LIFECYCLE — `enter` `exit`: the element joining or leaving the DOM. `exit` is the one
  thing CSS cannot do alone (the framework holds the element in the tree until it finishes).
- TIMELINE — `view` `scroll`: PROGRESS-driven, not time-driven. Reveal-on-scroll and
  parallax, at zero JS runtime cost. `view` = this element's passage through the viewport;
  `scroll` = the scroll container's total progress.

PROPERTIES: scale, opacity, translate-y, translate-x, rotate. Plus the reserved key `stagger` — a DURATION (`'40ms'`), not a preset:
it is the delay STEP between siblings arriving together, which is what turns a list
that appears into a list that arrives.

```
<card motion:view={{ opacity: 'fade', translate-y: 'spring:gentle' }}>reveal on scroll</card>
<row motion:enter={{ opacity: 'fade', stagger: '40ms' }}>cascades in</row>
<button motion:press={{ scale: 'press' }}>tactile</button>
```

PRESETS (closed set — an unknown one fails the build):

bounce, fade, fade-out, marquee, marquee-reverse, press, pulse, release, spring:bouncy, spring:deliberate, spring:gentle, spring:snappy

## Behavior — `use:` attaches, functions compose

ONE RULE: **if it touches the DOM it is an action; if it returns state it is a
function.** "use" means exactly one thing in this language — the `use:` directive.

- `use:action` (template) — behavior bound to an element. `Action<P>`: takes the node
  (+ an optional reactive param), returns `{ update?, destroy? }`. It replaces the
  ref + effect + cleanup triad entirely. Yours work exactly like the built-ins:
  `import { myAction } from './my-action'` then `use:myAction={param}`.
- COMPOSITIONS (`@ship/sui-std`) — plain functions that combine the reactive
  primitives and return signals. `form()`, `selection()`, `filteredList()`. There is
  no type, no registration, no lifecycle contract — nothing to author against, which
  is why anyone can write one. Call it in the `<controller>`, and the signals it
  returns are ordinary scope members the template binds to.

## State + imports

State lives in the `<controller>` — a raw `<script>` is banned, and the `<state>`
directive is retired. `controller(fn)` is ONE function, no sections: whatever it
RETURNS is the template's scope — state signals, derived values, plain helpers, and
event handlers alike, all as ordinary object properties.

```
<controller>
  import { controller, signal, derived } from '@ship/sui-runtime'
  import { selection } from '@ship/sui-std'

  export default controller((ctx) => {
    const rows = signal([])
    const sel = selection(rows, (r) => r.id)
    return { rows, sel }
  })
</controller>
```

Mutation is ALWAYS `signal.set(newValue)` (or `signal.set(prev => next)`). Lifecycle
is ambient, not a section — call `mount(fn)` (fires once after this instance's DOM
connects; a returned function is cleanup run on dispose) or `onCleanup(fn)` (runs on
dispose) from anywhere in the setup call graph, including a composition function
called from setup. Both are auto-injected — no import needed.

Import primitives from `@ship/sui-runtime` — the front door. Never from
`@ship/sui-runtime/internal`: that is the COMPILER's ABI (`bindFor`, `attachRef`,
`runAction`, …). If you are typing a symbol from there, you are hand-writing something
the compiler emits.

Reactivity: `signal` `derived` `effect` `batch` `untrack` `shared`. Reach for
`effect` rarely — it is the escape hatch, not the pattern. Cleanup is automatic: an
effect created during setup dies with the component.

Control flow: `{#if cond}…{/if}`, `{#for item of items key={item.id}}…{/for}`
(the `key=` is required — without it the reconciler falls back to positional matching
and loses DOM identity on reorder).

## Runtime CSS — the `(--x)` binding

ONE RULE: **scope owns props, the controller owns state** — there is no state block
in scope; state is code, not a declaration table. `style:` is gone; a `style:` use
refuses with a diagnostic that teaches this.

`sx` reads runtime values through `(--name)` (camelCase → kebab, e.g. a prop or
signal named `rowY` reads as `(--row-y)`): `translate-y-(--row-y)`, `bg-(--hue)`. When
`(--name)` matches a declared prop or a value `setup()` returns via `signal(...)`, the
compiler registers a typed CSS `@property` (a `number` gets `syntax: '<number>'`, so a
CSS transition on it tweens natively, no JS) and reflects the value onto the host as an
inline custom property, kept live automatically — no action, no manual `effect`. A name
never read via `(--x)` gets no wiring; an unmatched name is a compile error with a
did-you-mean.

Runtime GEOMETRY (a virtualizer offset, a drag position — not a prop, not scope
state) stays on `use:` actions: a named, typed action
(`use:virtualRow`, `use:eventSpan`, `use:rect`, `use:zoomPan`, `use:swatch`, …) writes
its own fixed custom property; sx reads it the same way, `(--name)`. `el.style` stays
closed — actions gain no styling powers beyond the one property they own.

### Native reskins (bare HTML tags the framework styles)

- `<a>` — Anchor — when `variant` is set, becomes a button link. Tone rides the global [tone] channel; hover shifts the fill toward the tone. (`variant=|default|solid|soft|outline|ghost`)

- `<button>` — Button — bare `<button>` IS the design system's button. tone/size ride the framework channels; variant chooses default/solid/soft/outline/ghost. (`variant=|default|solid|soft|outline|ghost`, `size=xs|sm|md|lg`, `tone=default|primary|info|success|warning|destructive|accent|muted`, `disabled`)

- `<details>` — Disclosure / accordion — bare `<details>`/`<summary>` is the design-system disclosure. Stacked adjacents merge into an accordion. Open/close animates natively. (`open`)

- `<dialog>` — Modal / sheet — bare `<dialog>` IS the design-system modal. `side=` docks it as a sheet; showModal() gives backdrop, ESC, focus-trap, focus-return for free. (`open`, `size=sm|md|lg|full`, `backdrop=blur|solid`, `side=start|end|top|bottom`)

- `<fieldset>` — Form group — bare `<fieldset>`/`<legend>` is a bordered section with the legend riding the top edge. `disabled` dims the whole group. (`disabled`)

- `<hr>` — Separator — horizontal by default; `orientation=vertical` and `variant=dashed` are attribute-keyed. tone tints the rule. (`orientation=horizontal|vertical`, `variant=solid|dashed`, `tone=default|primary|destructive`)

- `<html>` — Document root — the `html:has(dialog[open])` scroll-lock rule freezes the page while a native modal is open. No JS scroll-lock required. (presence / value via attribute)

- `<input>` — Text entry — bare `<input>` (text/email/etc.), `<textarea>`, `<select>` are the design-system field. tone/size/invalid mirror the button contract. (`type=text|email|password|number|search|tel|url|date|time|datetime-local|month|week|file|color|checkbox|radio|range|submit`, `tone=default|primary|info|success|warning|destructive|accent`, `size=xs|sm|md|lg`, `invalid`, `disabled`, `placeholder`)

- `<input[type=checkbox]>` — Checkbox — native appearance:none checkbox painted as a tone-filled square with a baked-white check. Indeterminate = tri-state. (`checked`, `indeterminate`, `invalid`)

- `<input[type=color]>` — Color swatch — rounded swatch button (not a text field). The platform's value is the selected color; the skin themes the swatch frame. (`value`, `disabled`)

- `<input[type=file]>` — File picker — keeps the field box, restyles the platform's file picker as a small secondary button. Use with `<div dropzone use:dropzone>` for drag-and-drop. (`accept`, `multiple`, `disabled`)

- `<input[type=radio]>` — Radio — native appearance:none radio painted as a tone-filled circle with a background-punched dot. (`checked`, `invalid`)

- `<input[type=range]>` — Slider — native appearance:none range, rebuilt as a tone-tinted rail with a white thumb ringed in the tone. size drives track/thumb thickness. (`value`, `min`, `max`, `step`, `size=sm|md|lg`)

- `<legend>` — Fieldset caption — semibold text-sm riding the top edge of a `<fieldset>`. Inherits the fieldset's own paddings. (presence / value via attribute)

- `<meter>` — Gauge — value-in-range; fill reflects WHICH band the value falls in (success/warning/destructive), not just how full. Distinct from `<progress>`. (`value`, `min`, `low`, `high`, `max`, `optimum`, `size=sm|md|lg`)

- `<optgroup>` — Option list caption — semibold muted label inside a native `<select>`'s popup. Groups options without changing the value model. (`label`, `disabled`)

- `<output>` — Form result — tabular figures so recomputes don't jitter. The native element for displaying a derived input value. (`for`, `form`)

- `<progress>` — Progress bar — determinate when `value` is set, indeterminate (sliding sheen) when not. tone tints the fill. (`value`, `max`, `size=sm|md|lg`)

- `<select>` — Picker — native `<select>` with the OS arrow replaced by a theme-aware chevron. option/optgroup reset so the popup is themed too. (`size=xs|sm|md|lg`, `tone=default|primary|info|success|warning|destructive|accent`, `invalid`, `disabled`, `multiple`)

- `<span>` — Status dot (`<span dot>`) and skeleton placeholder (`<span skeleton>`). tone rides the global channel; pulse animates the dot. (`dot`, `skeleton`, `size=sm|md|lg`, `shape=block|circle|text|line`, `pulse`)

- `<summary>` — Disclosure trigger — semibold trigger header inside `<details>`. Chevron rotates 180° and brightens to --foreground on open. (presence / value via attribute)

- `<table>` — Data table — STRUCTURAL primitive, zero JS. Variants ride the table itself (`[dense] [striped] [hoverable] [bordered]`); `<thead sticky>` pins the header; `[numeric]` columns right-align on tabular figures. (`dense`, `striped`, `hoverable`, `bordered`)

- `<tbody>` — Table body — row-group container inside `<table>`. CSS resets the trailing row's bottom border so a table reads as a single sheet. (presence / value via attribute)

- `<td>` — Table cell — body row cell. `[numeric]` right-aligns on tabular figures; bordered tables add a 1px cell border. (`numeric`)

- `<textarea>` — Multi-line text — shares the field surface with `<input>`. `rows=`/min-height scales the visible line count; vertical-only resize. (`rows`, `cols`, `size=xs|sm|md|lg`, `tone=default|primary|info|success|warning|destructive|accent`, `invalid`, `disabled`, `placeholder`)

- `<th>` — Table header cell — de-emphasized (muted-foreground) header; the body carries the data. `[numeric]` right-aligns on tabular figures. (`numeric`, `scope=row|col|rowgroup|colgroup`)

- `<thead>` — Table head — `[sticky]` pins the header to the scroll container top with a background to defeat bleed-through. (`sticky`)

- `<ul>` — Listbox — a `<ul role='listbox'>` becomes a widget surface (zero list markers, no default padding). A plain `<ul>` keeps the document-list reset; the role distinguishes widget use. (`role=listbox`)


## When the compiler rejects you

The rejection IS the documentation: every sx/lint error names the allowed
values. Do not work around an error with a `<style>` escape or an inline
style — if the vocabulary genuinely cannot express the design, STOP and
report it as a language gap.
